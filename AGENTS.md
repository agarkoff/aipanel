# Правила проекта

## Фича готова и проверена — один запуск

Не собирать и не пушить вручную по частям: после того как фича доделана и проверена, запустить

```powershell
pwsh -File scripts/release.ps1 -Message "Панель: ..." -Body "что и почему"
```

Скрипт сам: индексирует рабочую копию, прогоняет `cargo test --workspace` и `node --check` для правленых `.js`, при изменениях агента или протокола собирает release-exe и заменяет **обе** установленные копии (`~/.local/bin` и `~/.aipanel/bin`) с остановкой, переименованием старого файла и проверкой соединения, при изменениях сервера или статики пересобирает образ панели в Docker и сверяет отдаваемые файлы с репозиторием, коммитит, пушит в текущую ветку и ждёт, пока боевая панель начнёт отдавать новые файлы.

Флаги: `-SkipAgent`, `-SkipPanel`, `-SkipDeploy` (не ждать боевую панель), `-NoPush`, `-DryRun` (только показать шаги). Скрипт коммитит **всё**, что есть в рабочей копии: если в ней лежат незакоммиченные правки другой задачи, сначала разберитесь с ними.

## После изменений обязательно пересобирать

- **Агент.** Протокол (`crates/proto`) общий для сервера и агента. После правок протокола, команд или логики агента пересобрать его:
  ```sh
  cargo build --release -p aipanel-agent
  ```
  Затем заменить и перезапустить запущенные копии `aipanel-agent` на машинах. Старый агент не знает новых команд: сервер отправит её, агент ответит `unknown variant …` и команда зависнет без ответа (так было с `delete`).
- **Сервер.** Статика (`crates/server/static/*`) встроена в бинарник сервера. После правок интерфейса пересобрать и переразвернуть сервер, иначе браузер продолжит получать старую версию:
  ```sh
  cargo build --release -p aipanel-server   # или docker compose up -d --build
  ```
- **Перед коммитом:** `cargo test --workspace`; для `app.js` — `node --check crates/server/static/app.js`.

## Обновление установленного агента на Windows

1. Остановить: `aipanel-agent stop --config <agent.toml> --home <каталог>`.
2. Заменить exe. Запущенный файл блокируется, поэтому старый нужно сначала переименовать, затем скопировать новый.
3. Запустить и проверить: `aipanel-agent status --config <agent.toml> --home <каталог>`.

На этой машине копии агента лежат в `%USERPROFILE%\.aipanel\bin` (боевой, `wss://panel.example.com`) и `%USERPROFILE%\.local\bin` (локальный).
