# Правила проекта

## Выпуск фичи

Порядок — в `CLAUDE.md`: проверить, пересобрать изменённое, закоммитить **только файлы этой фичи**, запушить. Скрипта выпуска нет намеренно: `git add -A` захватил бы незаконченную работу других задач, которые могут лежать в том же дереве.

## Приватные данные — только в `.local`

Репозиторий публикуется на GitHub. Адрес боевой панели, панель хостинга и её проект, пути к копиям агента, каталог проекта на диске — всё это живёт в `.local/infra.md` (каталог в `.gitignore`), а в коде и документации его быть не должно. Отсюда же правило: скрипты берут адрес панели параметром, а не умолчанием, и подсказывают, где адрес лежит.

Проверка — в списке перед коммитом:

```sh
pwsh scripts/check-private.ps1
```

Скрипт читает файлы под git и новые, ещё не закоммиченные, печатает `файл:строка` и завершается с кодом 1, если нашёл приватную строку. Что именно искать, знает только эта машина: список лежит в `.local/private-patterns.txt` (по строке на правило, `#` — комментарий, `regex:` — регулярное выражение). В репозитории списка нет намеренно: он сам был бы подсказкой, что именно скрывают.

## После изменений обязательно пересобирать

- **Агент.** Протокол (`crates/proto`) общий для сервера и агента. После правок протокола, команд или логики агента пересобрать его:
  ```sh
  cargo build --release -p aipanel-agent
  ```
  Затем заменить и перезапустить запущенные копии `aipanel-agent` на машинах. Старый агент не знает новых команд: сервер отправит её, агент ответит `unknown variant …` и команда зависнет без ответа (так было с `delete`).
- **Сервер.** Статика (`crates/server/static/*`) встроена в бинарник сервера. После правок интерфейса пересобрать и переразвернуть сервер, иначе браузер продолжит получать старую версию:
  ```sh
  cargo build --release -p aipanel-server   # или docker compose up -d --build
  ```
- **Перед коммитом:** `cargo test --workspace`; для скриптов панели — `node --check` каждому файлу `crates/server/static/app.*.js`; `pwsh scripts/check-private.ps1`.

## Переводы строк

Во всём дереве — LF, на любой машине и при любом `core.autocrlf`. Это задаёт `.gitattributes` (`* text=auto eol=lf`), двоичные файлы (`.png`, `.ico`) не конвертируются. `.editorconfig` просит то же самое у редакторов. Правило нужно не из вредности: статика встроена в бинарник, и хеши файлов сравниваются напрямую — рабочая копия, коммит и боевой контейнер должны совпадать байт в байт.

Проверка:

```sh
git ls-files --eol | Select-String "w/crlf"   # пусто — всё в порядке
```

Если файл снова сохранили с CRLF (старый редактор, копирование, скрипт), вернуть LF так:

```sh
Remove-Item <путь>; git checkout -- <путь>
```

Массово, если разъехались многие файлы: `git ls-files | Remove-Item; git checkout -- .`. Команда заново выгружает всё из индекса, поэтому незакоммиченные правки в этих файлах пропадут — сначала закоммитить или отложить. `git checkout-index -f` на существующие файлы не действует: git считает их актуальными и не перезаписывает.

## Обновление установленного агента на Windows

1. Остановить: `aipanel-agent stop --config <agent.toml> --home <каталог>`.
2. Заменить exe. Запущенный файл блокируется, поэтому старый нужно сначала переименовать, затем скопировать новый.
3. Запустить и проверить: `aipanel-agent status --config <agent.toml> --home <каталог>`.

Копии агента на машине, где панель развёрнута, перечислены в `.local/infra.md` (каталог в `.gitignore`): там адреса, пути к exe и имена задач планировщика. В репозитории этих данных нет.

Модель голосового ввода (GigaAM v3, ~300 МБ) в exe не входит: агент скачивает её при первой записи в `<каталог агента>/models` — у копии с `--home` она своя. Замена exe её не трогает, поэтому после установки на новой машине первый голосовой ввод ждёт загрузки модели (панель пишет об этом в подсказке).
