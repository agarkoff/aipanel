# AiPanel: как выпускать фичу

Правила пересборки (что и когда собирать) — в `AGENTS.md`. Здесь — порядок выпуска: проверить, пересобрать, закоммитить только своё, отправить.

## 1. Проверить

```sh
cargo test --workspace
node --check crates/server/static/app.js      # если правился app.js
node tests/ui/feed.mjs                        # если менялась crates/server/static
```

Плюс проверить саму фичу так, как её будет использовать человек: в браузере — с компьютера и с телефона (узкий экран), в агенте — на живой сессии.

## 2. Пересобрать изменённое

**Агент** (`crates/agent`, `crates/proto`):

```sh
cargo build --release -p aipanel-agent
```

Затем заменить **обе** установленные копии — локальную (`%USERPROFILE%\.local\bin`) и боевую (`%USERPROFILE%\.aipanel\bin`), каждую по процедуре из `AGENTS.md`: `stop` → замена exe → `status` с проверкой соединения. Флаг `--config`/`--home` указывать на каталог этого экземпляра (`~/.aipanel` и `~/.aipanel`).

Запущенный exe держат обёртки `run-window` от открытых окон агента, поэтому переименовать его может не получиться. Тогда копировать поверх (`Copy-Item -Force`) и сверять `Get-FileHash` установленного файла с собранным: если хеши разные, exe всё-таки занят.

**Сервер** (`crates/server`, в том числе `static`):

```sh
docker compose up -d --build
```

Дождаться `/healthz` и сверить, что панель отдаёт файлы из репозитория: SHA-256 `http://127.0.0.1:18080` для `app.js`, `style.css`, `/`, `md.js`, `suggest.js`. `index.html` отдаётся по корню, а не по `/index.html` — иначе получите 404 и пустой файл. Если хеш не совпал, образ собран не из рабочей копии.

## 3. Закоммитить только файлы этой фичи

Скриптов выпуска нет намеренно: коммитить всё дерево нельзя, в рабочей копии может лежать незаконченная работа другой задачи.

1. Посмотреть `git status --short` и отобрать пути, которые относятся к задаче.
2. Индексировать их явно: `git add <путь> [<путь> ...]` — не `git add -A`, не `git add .`.
3. Проверить `git diff --cached`: чужих правок быть не должно. Если в тех же файлах есть чужие незакоммиченные изменения (так бывает, когда параллельно работает другая сессия), индексировать только свои участки: собрать версию файла как `HEAD` + свои правки, `git hash-object -w` и `git update-index --cacheinfo`.
4. Сообщение — одна строка в стиле проекта: `Панель: …`, `Агент: …`, `Сервер: …` или `Правила: …`. Тело — что и почему, если из заголовка это не очевидно.

## 4. Отправить и проверить боевую панель

```sh
git push origin master
```

Автодеплой идёт только с `master`: хостинг собирает образ и перезапускает контейнер по пушу. Если менялась статика, дождаться, пока https://panel.example.com начнёт отдавать новые файлы (сравнить хеши с локальными), и только потом считать фичу выпущенной.
